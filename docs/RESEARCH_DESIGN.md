# 研究问题、方法边界与评测设计

[返回项目首页](../README.md) · [有限注意力扩散](ATTENTION_DIFFUSION.md) · [使用与复现](USAGE.md)

本文承接原 README 中的研究假设、方法细节与实验设计。**实现说明、已有验证与待执行实验分别标明；评测方案不代表这些实验已经完成。** 文档拆分未新增算法或质量结论。

## 研究问题与可检验假设

项目将“记住历史”和“当前需要使用历史”分开研究。消息被保存、记忆被形成、候选被检索到，都不自动意味着它应该进入当前回复的上下文。

| 研究问题 | 待检验假设 | 必须面对的反例或对照 |
|---|---|---|
| RQ1：话题组织能否支持可靠的记忆形成？ | 在给定资源预算下，Episode 组织能够保留形成记忆所需的上下文 | Router 误并污染记忆、误拆丢失上下文；必须分开报告路由错误与 Writer 错误 |
| RQ2：形成记忆是否带来净收益？ | 相同读取预算下，形成记忆比直接读取原始历史更有助于当前对话 | 强原文检索加邻近消息或回复链可能已经足够；摘要可能丢失限定、时序或否定 |
| RQ3：关联传播是否有必要？ | 显式关系可以找回直接语义召回遗漏的有用材料 | 传播可能引入主题相近但用途无关的节点；图扩展也可能达到同等效果 |
| RQ4：适用性判断是否改善实际使用？ | 显式判断能减少无用或不受来源支持的上下文注入 | 额外模型成本、漏选、错误接受；需要评估最终回复而不只统计入选数量 |

这些是本实现支持研究的假设，不是已经得到实验支持的结论。当前优先问题是建立独立评测，先验证 RQ2 的净收益，再判断更复杂的传播机制是否值得保留。

## 对象与边界

| 对象 | 本项目中的定义 | 解释边界 |
|---|---|---|
| Event（原始事件） | 带稳定 ID、说话者、时间与正文的原始消息 | 是来源记录，不等于事实真值 |
| Episode（话题容器） | Router（路由器）分配的话题容器 | 同一容器不保证全部内容语义一致 |
| Temporary（临时记忆） | Episode 最近消息被 FIFO（先进先出工作上下文）挤出时形成的增量记录 | 允许保留未决指代、更新与冲突 |
| Final（长期记忆） | Episode 关闭后形成的长期节点、关系和来源引用 | 结构校验通过不等于语义正确 |
| 当前对话状态 `S` | 实际可见的近期消息、说话者及回复关系 | 不使用隐藏题目、标准答案或人工指定目标记忆 |
| 内部工作上下文 `C` | 通过适用性判断并满足字符预算的历史材料 | 不是最终回复，也不代表获得了对外披露授权 |

`scope` 是数据空间，通常对应稳定群聊 ID。研究与评测必须在同一空间、同一历史截点下比较方法，避免跨群或未来信息影响结果。

## 已实现方法及其约束

### 话题组织与记忆形成

写入采用“非生成式路由 + 生成式整理”的分工。两个冻结 CPU 判别分支处理新话题判断及候选归属，输入遵循 `two-judge-observable-v3`，使用路由时实际可见的历史。无候选时直接新建 Episode；调用方不通过传入 Episode ID 指定正确答案。

每个 Episode 独立维护 FIFO。当前网关容量为 12 条，每次挤出 6 条；挤出批次交给 Temporary Writer（临时记忆整理模型），Episode 关闭后进行 Final 整理。这个设计把模型调用放在批次与关闭阶段，同时引入需要测量的代价：等待时间、上下文截断、路由误差传播，以及临时结果与最终结果之间的信息变化。

Writer 输出接受结构和来源检查，保留实际事件、记忆引用及未决内容。检查可以限制不存在的引用和不合法的结构，但不能独立证明自然语言陈述被来源蕴含。对话中的陈述、系统抽取的关系和真实世界事实必须在分析中区分。

持久接收队列与显式失败恢复使执行状态可检查。接收成功只表示消息已保存；消息处理完成也不保证已经生成 Final。研究统计应分别记录接收、整理、关闭和读取的时间点。

### 以当前对话状态为条件的召回

读取输入是当前可见对话，而不是额外构造的隐藏问答题。默认线索计划组合关注说话者的稳定身份与最近可见消息，权重分别为 0.35 和 0.65；这些是固定实现参数，没有学习或校准为认知规律。

本地 BGE embedding（向量表示模型）负责语义表示，BGE reranker（重排模型）对候选重新排序。多线索排名通过加权倒数排名融合组合。系统保留模型指纹、图快照、来源信息及候选轨迹，以便重放和定位差异。

HTTP 提供三个读取分支：

| 分支 | 候选生成机制 | 用于回答的问题 |
|---|---|---|
| `formed_multiquery` | 多线索直接召回形成记忆 | 不依靠关系传播能做到什么？ |
| `graph_expansion` | 在相同关系通道中按最佳路径扩展 | 显式关系连接是否补足直接召回？ |
| `attention_diffusion` | 在图上迭代分配有限注意力，再按阈值选候选 | 多路累积与竞争是否带来额外收益？ |

后续使用共同的重排与候选预算设置，但三者不因此拥有相同的实际计算成本。扩散分支先执行出现阈值筛选，再进入共同重排；重排器不会补回未通过该阈值的节点。这一差异应纳入消融分析。扩散定义、参数与关系通道见 [有限注意力扩散](ATTENTION_DIFFUSION.md)。

底层比较模块还包含 `raw_retrieval`、`raw_window_retrieval` 和 `formed_retrieval`，可作为扩展评测的起点；当前 HTTP 接口只暴露上表三个分支，没有提供一键完成全套质量评测的入口。

### 适用性判断与有界上下文

候选召回与最终使用是两个独立步骤。默认 `autoSignificance=false`：系统返回候选和轨迹，但不自动把候选加入工作上下文。显式启用后，对非空候选最多执行一次真实模型判断，检查候选是否对当前状态有用途、是否得到来源支持、是否允许使用，并核验当前对话锚点。

仅满足合同的候选进入上下文打包。默认最多选择 4 条、检查预算 12、上下文字符预算 8000；完整记录只有在预算容纳时才加入。字符预算约束 `contextText`，不约束整个包含轨迹的 HTTP 响应，也不等价于 token（词元）预算。

判断结果仍是模型输出。评测需要独立判断它是否接受了无用材料、拒绝了关键材料，或误认来源支持；“选中了几条”不能作为正确率。

### 时间与状态边界

读取使用同一 `scope` 的历史快照，限制候选来源早于当前状态中最早的事件。同一空间存在未完成写入任务时拒绝读取；在返回并持久化审计前，再检查空间版本是否发生变化。该设计减少半完成状态与并发写入对比较的影响。

调用顺序应为：**先用当前状态读取，再按需要将当前消息写入。** 这些约束提供工程上的防泄漏措施；完整实验仍需检查数据划分、重复样本、标注信息和形成阶段是否引入额外泄漏。

## 待执行实验设计

本节是待执行的评测方案，不是已完成实验。

### 评测单位与数据划分

一个评测样本应包含：历史截点之前的原始事件、由该历史实际形成的记忆、截点处的真实可见对话状态，以及独立标注的有用来源与不可用材料。空召回或“不需要记忆”的状态也应纳入。

训练、开发与最终验证按会话或其他能够控制泄漏的单位隔离。参数只在开发集选择，最终验证前冻结代码、模型、图构建过程、预算和评分规则。Router 评估应使用自主运行形成的候选与历史状态；人工正确路由可作为误差上界诊断，但不能替代自主链路成绩。

### 最小对照组

| 比较 | 控制条件 | 主要解释 |
|---|---|---|
| 不使用历史 vs 强原文检索 | 相同当前状态、回复模型与输出预算 | 历史本身是否有帮助 |
| 强原文检索 vs 形成记忆直接召回 | 相同历史截点、语义模型和上下文预算；原文基线含邻近消息或回复链 | 记忆形成是否值得其成本与信息损失 |
| 直接召回 vs 图扩展 vs 注意力扩散 | 相同形成图、种子规则、重排器和预算；单独记录实际耗时 | 关系传播和多路累积是否提供额外收益 |
| 有 / 无适用性判断 | 相同候选集合与下游回复条件 | 判断是否减少错误注入，代价是多少 |
| 自主 Router vs 人工正确路由 | 相同 Writer 和读取方法 | 路由错误在完整链路中造成多大损失 |

“不使用历史”、下游回复评估以及完整自动评测编排需要另行实现。表中对照不能被理解为仓库已经交付这些实验结果。

### 评价维度

- **路由与形成质量**：误并、误拆；陈述的来源支持率；限定、否定、时序和冲突保留；未决内容是否被错误确定化。
- **读取质量**：按独立标注计算有用来源召回与入选精度，统计干扰项入选率、无记忆需求状态的误注入率，并区分候选失败与适用性判断失败。
- **下游效用**：在控制回复模型和预算后，评估回答正确性、相关性、无依据陈述及不当历史披露；报告无记忆与强原文基线。
- **资源代价**：CPU 内存与耗时、写入和判断的模型调用数、token 成本、上下文长度、积压与失败率；区分冷启动、暖缓存和执行顺序。
- **不确定性**：报告样本量、数据组成、按会话聚合的置信区间及失败案例。没有足够样本时保留描述性结果，不给出泛化结论。

扩散的必要消融包括移除关系、改变关系类型、移除竞争或种子回注，以及改变步数和阈值。先固定开发集选择过程，再执行独立验证，避免把多轮调参中的最佳结果当成方法优势。

| Writer / 适用性判断 | Codex CLI `0.159.3`，`gpt-6.1-sol`，`medium`；官方认证路径预检；单次预算 180 秒，无自动重试 |

Router 权重通过 [GitHub Release](https://github.com/longzhou23/xtw_memory/releases/tag/memory-minimal-20261005-router-v02) 附件提供，不进入源码历史。**该 Release 的源码标签早于读取链路加入；获取完整当前实现应使用 `main`，复核已有证据时使用对应提交。** BGE 模型由独立准备脚本下载并校验，不包含在 Router 权重包内；准备完成后本地读取推理离线运行。

真实 Writer 与适用性判断需要已登录的模型服务，会发送相关消息与来源材料并产生调用成本。固定模型名称和 CLI 版本有助于记录环境，但不能保证远端生成行为逐位一致。复现实验应另行保存调用时间、可用的服务版本信息、输入输出和失败记录。

源码与权重可获得，不等于实验结果完整可复现。发布质量结论前，还需补齐可分享的评测数据或可审查的数据协议、冻结划分、标注规则、运行脚本、参数、原始结果与统计过程，并将代码提交、模型指纹和数据版本逐项对应。

本项目处于开发期，不提供旧数据库兼容或数据迁移。配置或封存身份变化时使用新数据库，保留旧实验库和元数据，避免不同条件的结果被混合。

## 限制与研究推进顺序

当前证据不足以评估真实多人对话的长期收益。Router 错误会沿写入链路传递；生成式整理可能丢失信息或错误解释来源；关联传播可能放大无关节点；适用性模型可能误判。来源追踪和轨迹使这些问题可检查，并不自动消除它们。

当前实现面向小规模历史，采用完整索引与受限快照，不提供大规模检索性能结论。关闭条件、单 Episode 上限和历史容量限制也会改变可读取内容，不能在实验中当作无关部署细节。

后续工作应按以下顺序形成证据：

1. 冻结一套包含“不需要记忆”、多话题交错、跨时间更新和干扰项的独立当前状态评测集。
2. 在同一历史和预算下比较强原文基线与形成记忆，联合报告错误、下游效用和形成成本。
3. 只有在前一步观察到可靠收益后，再检验图扩展、扩散和适用性判断分别贡献了什么。
4. 将独立验证结果、失败案例与可复现实验材料一同发布，再讨论更大规模运行。
