# 小天文 Memory 备忘录：三关系联想网络、有限注意力与记忆涌现

**日期：2026-09-22**  
**状态：当前讨论阶段备忘 / 待下一轮 Demo 修订**  
**范围：Memory Recall / Associative Network，不涉及 Episode Router / Lifecycle 的重构**

---

# 0. 当前结论

这一轮讨论把 Recall 模型进一步收敛成了一个更干净的形式：

> **Node 保留丰富认知语义；Edge 只保留三种基础联想关系：因果、对立、相似；Attention 是所有节点共享的瞬时量纲。**

Recall 不再被理解为：

```text
Query
→ embedding similarity
→ Top-K memories
```

而是：

```text
Current Context
→ Seed Attention
→ 三关系联想网络上的稀疏扩散
→ 多路径汇聚
→ 全局竞争
→ Memory Emergence
→ Working Memory
```

总注意力始终有限：

\[
\sum_i A_i(t)=1
\]

系统目标不是“从库里搜出几条记忆”，而是：

> **让有限注意力在联想网络中流动，并让当前最有认知竞争力的记忆自己浮现。**

# 1. 为什么之前的 Demo 会出现“注意力涣散”

当前 Demo 的一个典型例子：

```text
Context:
“小天文喵是谁做出来的？”
```

实际扩散后却同时激活：

```text
longz
天文观测
流星雨
华理天文社社娘
Self identity memory
creator memory
助手 / 社娘
……
```

结果呈现为：

```text
小天文         ~0.30
其他一圈节点   ~0.06–0.08
```

这说明：

> **有限 Attention 能防止资源无限膨胀，但不能自动保证聚焦。**

原因不是简单的参数问题，而是旧公式中缺少“当前问题到底在沿什么认知方向思考”的机制。

---

# 2. 旧公式的问题

之前的 P0 公式大致是：

\[
G_{ij}=S_{ij}^{1/T}
\]

\[
Q_{ij}=A_iG_{ij}
\]

满足阈值的边参与分配：

\[
Q_{ij}\ge\theta_{flow}
\]

局部分配：

\[
Z_i=K_{self}+\sum_jG_{ij}
\]

\[
F_{i\to i}=A_i\frac{K_{self}}{Z_i}
\]

\[
F_{i\to j}=A_i\frac{G_{ij}}{Z_i}
\]

之后做：

```text
Multi-path accumulation
→ Context Anchor
→ Emergence Threshold
```

这个版本解决了：

- 高 Attention 节点可以激活更多边
- 低 Attention 节点只能维持少数强关联
- 多路径可以汇聚
- 总 Attention 可以守恒

但暴露出两个新问题。

---

# 3. 问题 A：Hub 节点会“泄洪”

如果一个节点有很多 outgoing edges：

```text
小天文
├── longz
├── 流星雨
├── 天文观测
├── 社娘
├── 天气
├── 世界计划
├── ...
```

旧公式中：

\[
Z_i=K_{self}+\sum_jG_{ij}
\]

随着出边数量增加：

\[
\sum_jG_{ij}
\]

会越来越大。

于是：

\[
\frac{K_{self}}{K_{self}+\sum_jG_{ij}}
\]

越来越小。

结果：

> **节点连接越多，越容易把自己的 Attention 大量撒出去。**

这对长期 Memory 图非常危险，因为真正的大图里高频人物、地点、主题会逐渐成为 Hub。

所以需要把两个问题拆开：

```text
这轮允许向外流多少 Attention？
```

和：

```text
流出去的 Attention 应该沿哪些边分配？
```

---

# 4. 问题 B：Context 只有“实体”，没有“思考方向”

问题：

```text
“小天文喵是谁做出来的？”
```

不仅包含：

```text
Node cue:
小天文喵
```

还包含：

```text
Relation intent:
寻找原因 / 来源
```

如果 Context 只把“小天文喵”作为 Seed：

```text
小天文喵 = 1.0
```

网络只能理解：

> “围绕小天文喵联想。”

它不知道当前应该偏向：

```text
原因
创建来源
谁导致了它存在
```

所以“longz、流星雨、天文观测、社娘身份”都会被当成普通强关联一起扩散。

---

# 5. 一个重要纠偏：Edge 只有三种关系

这一轮确认：

**Associative Layer 不应该变成 Knowledge Graph。**

不应该继续引入：

```text
created_by
likes
located_in
owns
has_role
plays
member_of
contains
...
```

这些具体谓词属于：

> **Node / Memory / Proposition 的语义内容**

而不是 Associative Layer 的基础关系。

我们最初约定的 Edge 只有三类：

```text
1. CAUSAL
   因果

2. OPPOSITION
   对立

3. SIMILARITY
   相似 / 联想接近
```

这三种关系继续作为网络的唯一基本 Edge type。

---

# 6. 三种关系的含义

## 6.1 CAUSAL — 因果

表示：

```text
A 导致 B
A 是 B 的来源
A 是 B 的原因
A 促成了 B
```

例如：

```text
longz
  │
  │ CAUSAL
  ▼
小天文
```

或者更完整地：

```text
longz
  │ CAUSAL
  ▼
“longz 创建了小天文”
  │ CAUSAL
  ▼
小天文
```

“创建”本身存在于 Memory / Proposition 内容里。

Edge 只需要知道：

```text
这是因果关联
```

CAUSAL 天然有方向。

Recall 时可以：

```text
顺因果：
原因 → 结果

逆因果：
结果 → 追溯原因
```

例如：

```text
“小天文是谁做出来的？”
```

就是从结果节点逆向追溯原因。

---

## 6.2 SIMILARITY — 相似 / 联想接近

Similarity 不仅仅是：

> “两个东西长得像。”

更广义地承担：

```text
语义接近
共现
同一主题
经常一起想到
属于同一认知团
普通自由联想
```

例如：

```text
NICEICK
   │ SIMILARITY
世界计划
   │ SIMILARITY
星乃一歌
```

也可以是：

```text
小天文
   │ SIMILARITY
天文观测
```

这将成为最常见的普通 Recall 路径。

---

## 6.3 OPPOSITION — 对立

表示：

```text
相反
冲突
互斥
对照
```

例如：

```text
在学校
   │
OPPOSITION
   │
不在学校
```

或者：

```text
喜欢黑白摄影
   │
OPPOSITION
   │
不喜欢黑白摄影
```

这类关系未来对：

- 冲突记忆
- 状态更新
- 反例
- 认知修正

都可能很重要。

# 7. Node 与 Edge 的职责重新明确

## Node

Node 可以是任意认知对象：

```text
Person
Alias
Self
Memory
Episode
Proposition
Concept
Location
Object
Activity
Goal
Question
Procedure
Role
Time
...
```

原则：

> **任何值得独立持有 Attention 的认知对象，都可以成为 Node。**

Node 中可以保留复杂语义。

例如：

```text
“小天文由 longz 创建”
“NICEICK 喜欢世界计划”
“Amaryllis 在徐汇”
“不爱记笔记有一台 8SE”
```

这些内容不需要被强迫拆成几十种 KG relation。

---

## Edge

Edge 极度简化：

```ts
type RelationType =
  | "CAUSAL"
  | "SIMILARITY"
  | "OPPOSITION";

interface Association {
  source: NodeId;
  target: NodeId;
  type: RelationType;
  strength: number;
}
```

其中：

```text
strength
```

仍然表示长期联想强度。

---

# 8. Context 不只包含 Seed Node

新的 Context 应至少包含两部分：

```text
1. Node Attention Seeds
2. Relation Mode / Relation Intent
```

例如：

```text
“小天文喵是谁做出来的？”
```

可以解析为：

```text
Node Seed:
小天文喵

Relation Intent:
CAUSAL
并且偏向逆因果追溯
```

普通问题：

```text
“说到小天文你会想到什么？”
```

则更偏：

```text
SIMILARITY
```

如果问：

```text
“有什么记忆和这个说法冲突？”
```

则更偏：

```text
OPPOSITION
```

---

# 9. Relation Context 可以是三维权重

不一定每次只选一个关系类型。

Context 可以维护一个三维关系向量：

\[
C_R=
(causal,\ similarity,\ opposition)
\]

例如：

## “小天文是谁做出来的？”

\[
C_R=
(0.85,\ 0.10,\ 0.05)
\]

## “说到小天文你想到什么？”

\[
C_R=
(0.15,\ 0.80,\ 0.05)
\]

## “什么和这个说法矛盾？”

\[
C_R=
(0.05,\ 0.10,\ 0.85)
\]

这只是示意，不是最终固定数值。

---

# 10. Context 对边的作用

原来：

\[
G_{ij}=S_{ij}^{1/T}
\]

现在应该变成：

\[
\boxed{
G_{ij}
=
S_{ij}^{1/T}
\cdot
C_R[type(i,j)]
}
\]

其中：

- \(S_{ij}\)：长期 Association Strength
- \(T\)：Temperature
- \(type(i,j)\)：三种 Edge type
- \(C_R\)：当前 Context 对三类关系的偏好

所以：

> Context 不直接选 Memory。

它只是改变：

> **当前哪些类型的认知通路更“导电”。**

这和 Top-K Retrieval 是本质不同的。

---

# 11. 注意力依赖的边激活

边的当前 Flow Potential：

\[
\boxed{
Q_{ij}
=
A_i
\cdot
G_{ij}
}
\]

也就是：

\[
Q_{ij}
=
A_i
\cdot
S_{ij}^{1/T}
\cdot
C_R[type(i,j)]
\]

边只有在：

\[
Q_{ij}\ge\theta_{flow}
\]

时才参与扩散。

这保留了原来的核心想法：

```text
高 Attention
→ 能带起更多弱关联

低 Attention
→ 只能带起少数强关联

非常低 Attention
→ 无法继续扩散
```

---

# 12. Bounded Outflow — 限制每轮向外流量

为了避免 Hub 泄洪：

每个节点一轮向外流出的 Attention 必须有上限。

定义：

\[
L_{\max}\in[0,1]
\]

例如：

```text
maxLeak = 0.45
```

则：

```text
当前 Attention = 0.30
```

这一轮最多只能向外流：

\[
0.30\times0.45=0.135
\]

无论这个节点有：

```text
3 条边
30 条边
300 条边
```

都不能突破这个 outward budget。

---

# 13. 新的局部分配公式

先计算有效边：

\[
Q_{ij}
=
A_i
S_{ij}^{1/T}
C_R[type(i,j)]
\]

去掉阈值以下的部分：

\[
E_{ij}
=
\max
\left(
0,
Q_{ij}-\theta_{flow}
\right)
\]

节点这一轮允许流出的总 Attention：

\[
\boxed{
O_i
=
\min
\left(
L_{\max}A_i,
\sum_jE_{ij}
\right)
}
\]

然后在 eligible edges 之间分：

\[
\boxed{
F_{ij}
=
O_i
\frac{E_{ij}}
{\sum_kE_{ik}}
}
\]

节点自己保留：

\[
\boxed{
F_{ii}
=
A_i-O_i
}
\]

这样就避免了：

> degree 越高，节点越容易把 Attention 全撒光。

---

# 14. Multi-Path Convergence 继续保留

所有路径必须相加：

\[
D_j
=
\sum_iF_{ij}
\]

例如：

```text
A → X   +0.04
B → X   +0.05
C → X   +0.06
```

则：

\[
D_X=0.15
\]

不能：

```text
取最大
取平均
只保留最强边
```

这仍然是 Memory Emergence 的核心机制。

---

# 15. Competition / Lateral Inhibition

这一轮发现：

> Attention 守恒并不自动产生“聚焦”。

因此在汇聚完成后，需要一个全局竞争步骤。

扩散后：

\[
D_j
\]

执行：

\[
B_j=D_j^\gamma
\]

其中：

\[
\gamma>1
\]

再归一：

\[
\boxed{
H_j=
\frac{D_j^\gamma}
{\sum_kD_k^\gamma}
}
\]

例如：

```text
longz      0.25
流星雨      0.08
```

原来差距：

```text
3.1×
```

当：

\[
\gamma=1.5
\]

之后，大约变成：

```text
5.4×
```

这意味着：

> 已经略占优势的认知方向，会进一步压制次要方向。

这才真正形成“注意力聚焦”。

---

# 16. Competition 对 Memory Emergence 的意义

Multi-path convergence 产生：

```text
弱路径 A
+
弱路径 B
+
弱路径 C
→ Memory X 略微领先
```

Competition 再把这个优势放大：

```text
X 稍强
→ 全局竞争
→ X 明显变强
→ 跨过 Emergence Threshold
```

因此会形成：

> “等等，我突然想起来了。”

这比只靠一个固定 threshold 更接近我们想模拟的现象。

---

# 17. Context Anchor 继续保留

为了避免联想无限漂移：

\[
A(t+1)
=
(1-\lambda)H+\lambda C
\]

其中：

- \(H\)：竞争后的 Attention
- \(C\)：初始 Context Attention
- \(\lambda\)：Context Anchor

例如：

```text
contextAnchor = 0.12
```

可以理解为：

> 88% 跟着当前联想变化，12% 始终记得“我原本正在想什么”。

# 20. 三层机制的职责

现在可以把 Recall 动力学非常清楚地拆成三层。

回答：

> **我长期以来容易把什么和什么想到一起？**

表现为：

```text

OPPOSITION
+

```

回答：

> **我现在正在沿什么方向思考？**

```text

+
```

回答：


Dream 未来不再是：

```text

→ 抽 SVO

```

```text

↓

↓
```

Dream 学的重点将变成：

```text

```

# 26. 当前 Research Hypothesis

更新后的研究假设：

> **Long-term agent recall can be modeled as constrained, context-conditioned attention diffusion over a heterogeneous associative memory network whose edges are restricted to causal, oppositional, and similarity relations. A fixed global attention budget is redistributed through attention-dependent sparse propagation, bounded node outflow, multi-path convergence, and global competition; memories enter working memory through emergence rather than fixed Top-K retrieval.**

中文：

> **长期 Agent Recall 可以建模为一种受限、受 Context 调制的注意力扩散：异构认知节点通过“因果、对立、相似”三种基本联想关系组成网络；固定总量的 Attention 通过稀疏传播、节点有限外流、多路径汇聚与全局竞争重新分配，最终以涌现而非固定 Top-K 的方式进入 Working Memory。**

# 28. 当前最重要的设计原则

可以压缩成六条：

1. **Node 可以是任意认知对象。**
2. **Edge 只有因果 / 对立 / 相似三种。**
3. **Attention 是所有节点共享的唯一瞬时量纲。**
4. **Context 不返回答案，只改变当前哪些路径更容易导通。**
5. **多路径汇聚产生“突然想起来”的可能。**
6. **Competition 负责把扩散后的多个候选重新聚焦成 Working Memory。**
